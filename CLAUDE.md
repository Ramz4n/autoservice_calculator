# Alexan — программа для автосервиса (Python, CustomTkinter, MariaDB)

Отвечать по-русски.

## Автотесты — обязательно

В проекте есть автотесты: `tests/` (описание — `tests/README.md`).

- **После изменений** в формах, базе или логике (`autoservice_calculator.py`, `database.py`,
  `db_schema.py`, `plates.py` и т.п.) запускать только новый или связанный тест по части имени:
  `python tests/run_all.py <часть имени>` — и сообщить итог. Полный `python tests/run_all.py`
  (идёт больше 10 минут) — только по просьбе (например, перед коммитом).
  Упавший тест — сначала понять: ошибка программы или теста.
- **Новая функция или исправление** — дописать проверки:
  позитивные в `tests/test_positive.py` (сохраняется то, что нужно) и
  негативные в `tests/test_negative.py` (неверный ввод → предупреждение и ни одной записи в базе),
  **связи между разделами** в `tests/test_effects.py` — куда ещё действие должно дойти и откуда уйти:
  работа → зарплата в «Отчётах» (после «Выполнено»), доход/прибыль, «Статистика»; удаление → всё это убирается;
  премия/выплата → расход в «Финансах»; склад → наряд. Проверять и появление, и исчезновение.
  Обновить таблицу «Что покрыто» в `tests/README.md`.
- Тесты пишут в базу и работают **только на тестовой базе** (флаг `ALEXAN_TEST_DB=1` в `config/.env`).
  Никогда не ставить этот флаг и не запускать тесты на базе клиента.

## Боевая база клиента — не портить

Фирма-клиент каждый день работает в программе с настоящей базой; потерянные данные не восстановить
(бэкапы раз в день). Любое изменение должно быть безопасно для неё:

- Схема (`db_schema.py`) — только добавлять: новые таблицы / колонки с NULL или DEFAULT, миграции
  повторяемые (проверка, есть ли уже). Без согласия — никаких DROP / RENAME / сужения типов.
- DELETE / UPDATE — по точному WHERE (id); проверять, какие ещё строки могут задеть.
  Массовые правки данных — только с согласия и после бэкапа.
- Новые правила в формах учитывают старые записи без этих данных: открываются, показываются, считаются.
  Отчёты / зарплата / финансы по старым данным не должны тихо пересчитаться иначе — если меняется, сказать.
- Релиз не затирает файлы клиента (`config/settings.json`, `.env`, `license.key`, бэкапы).
- К базе клиента не подключаться. Сомнение, не заденет ли изменение его данные, — спросить.

## После изменений

- Дописать `CHANGELOG.md` сверху (версия = VERSION + 1, её поднимает `package_release.bat`), обновить `README.md`,
  если меняется устройство базы или работа программы.
- Тексты интерфейса — во всех 5 языках `config/locales/*.json` (ru, en, sr, hy, ka).

## Устройство (коротко)

- Поиск машины по госномеру — один на все формы: `AutoServiceApp.find_car_by_plate`.
  Правила госномеров (латиница → кириллица, проверка ошибок) — `plates.py`.
- Марка и модель — одни на все формы: `car_catalog.py` (`CarAutocomplete` — подсказки,
  `catalog_car_names` — при сохранении только из справочника «Марки и модели»).
- Числа из полей (цены, суммы, количество, процент) — только через `input_rules.py` (`parse_money` и др.).
- Должности: `positions.is_master = 1` — «работает с машинами» (выбираются в «Добавить работу»,
  получают процент, считаются местами в «Записать клиента»).
- Telegram-бот (`tgbot/`) не используется, онлайн-запись (`web_sync.py`) пока не работает — их не трогать без запроса.
