# Выпуск обновлений через GitHub Releases — инструкция

Приложение само проверяет обновления, пока запущено (каждые
`UPDATE_CHECK_INTERVAL_MS`, см. `autoservice_calculator.py`), и предлагает
их поставить. Источник — последний релиз публичного репозитория
`Ramz4n/auto_releases` (`updater.py`, константа `GITHUB_REPO`).

---

## Как устроено (коротко)

Сборка — `--onedir`: `.exe` это только лаунчер, реальный код и зависимости
лежат рядом в `_internal/`, плюс `config/` (переводы, настройки) и `main/`
(бэкенд). Поэтому в релиз заливается **весь этот набор одним `.zip`**, а не
голый `.exe` — иначе после обновления версии `.exe` и `_internal/` разъедутся
и приложение не запустится.

`config/.env` и `main/.env` при сборке содержат боевые секреты (пароль
MySQL, токен Telegram-бота, ключи SMSC) — их **нельзя** заливать на
публичный GitHub. Поэтому архив для релиза собирается не вручную, а через
`package_release.bat`, который сначала вычищает секреты.

---

## 1. Собрать новую версию

1. Открыть `updater.py`, поднять номер версии:
   ```python
   APP_VERSION = "1.0.1"
   ```
2. Запустить `build.bat` — соберёт `dist\autoservice_calculator\`.
3. Запустить `package_release.bat` — соберёт чистый архив
   `release\autoservice_calculator.zip` (без `.env`, `license.key`,
   `license_cache.json`).

Перед следующим шагом можно на всякий случай открыть архив и глазами
убедиться, что там нет `.env` и `license.key`.

---

## 2. Опубликовать релиз на GitHub

1. Открыть **https://github.com/Ramz4n/auto_releases/releases/new**
2. **Tag**: ввести новый тег и нажать "Create new tag on publish":
   - `v1.0.1` — обычное обновление (у пользователя будет выбор "Обновить" / "Не сейчас")
   - `v1.0.1-force` — обязательное (окно нельзя закрыть, пока не обновится)

   Версия в теге должна совпадать с `APP_VERSION`, который вы только что
   поставили в `updater.py` (без буквы `v` в самом `APP_VERSION`,
   `v` — только в теге).
3. **Release title** — что угодно, например `1.0.1`.
4. **Description** — текст, который увидит пользователь в окне обновления
   ("Что нового"). Например:
   ```
   — Исправлена ошибка со складом при повторном добавлении запчасти
   — Добавлено примечание в диалог выбора запчастей со склада
   ```
5. **Attach binaries** — перетащить туда `release\autoservice_calculator.zip`.
6. Нажать **Publish release**.

Готово — больше ничего делать не нужно. Все клиенты подхватят обновление
сами при следующей проверке (интервал — в `autoservice_calculator.py`).

---

## 3. Как это выглядит у клиента

- Приложение раз в `UPDATE_CHECK_INTERVAL_MS` тихо стучится в GitHub API.
- Если есть новая версия — всплывает окно с changelog и кнопками
  "Обновить" / "Не сейчас" (или только "Обновить", если тег был с `-force`).
- При нажатии "Обновить" — скачивается `.zip`, приложение закрывается,
  bat-скрипт разворачивает новую версию поверх старой и перезапускает
  программу.
- Личные данные клиента (`license.key`, `license_cache.json`, `.env`,
  `settings.json` — % мастера, `spare_parts.txt` — список запчастей)
  при этом не трогаются и не перезаписываются.

## Частые ошибки

| Симптом | Причина |
|---|---|
| Окно обновления не появляется | Тег в релизе ≤ `APP_VERSION` в `updater.py`, либо в релизе нет `.zip`-файла среди asset'ов |
| "Доступно обновление" на версию, которая уже стоит | Забыли поднять `APP_VERSION` перед сборкой |
| После обновления приложение не запускается | Архив собирали вручную (не через `package_release.bat`) и он не соответствует структуре `dist\autoservice_calculator\` — `.exe` должен лежать прямо в корне архива (или в одной вложенной папке) |
| У клиента слетели настройки/лицензия после обновления | Такого быть не должно — `apply_update()` в `updater.py` явно исключает эти файлы из перезаписи (`robocopy /XF`). Если всё же слетело — баг, требует разбора |

## Проверка перед боевым релизом

Сейчас `UPDATE_CHECK_INTERVAL_MS` в `autoservice_calculator.py` выставлен
на 5 минут — для тестирования, чтобы не ждать часами. **Перед тем как
раздавать программу клиентам**, поменять на боевой интервал:

```python
UPDATE_CHECK_INTERVAL_MS = 6 * 60 * 60 * 1000  # 6 часов
```
