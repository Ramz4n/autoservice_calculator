=============================================================================
                          ЭТАП 4: ЛОГИКА АНАЛИЗА
=============================================================================

4.1. Функция get_car_maintenance_status(car_id, current_mileage):

    1. Загрузить maintenance_schedule.json
    2. Получить все работы по car_id из таблицы works
    3. Для каждого пункта обслуживания:
       a. Искать в description совпадения с keywords (регистронезависимо)
       b. Найти последнюю такую работу
       c. Если работа найдена и есть mileage:
          - km_since = current_mileage - work_mileage
          - Определить статус:
            * km_since < interval_min: "OK" (зелёный)
            * interval_min <= km_since <= interval_max: "СКОРО" (жёлтый)
            * km_since > interval_max: "ПРОСРОЧЕНО" (красный)
       d. Если работа не найдена:
          - Статус "НЕТ ДАННЫХ" (серый)

4.2. Результат - список:
    [
        {
            "name": "Замена масла ДВС",
            "status": "overdue",  # ok / soon / overdue / unknown
            "last_mileage": 45000,
            "last_date": "2024-01-15",
            "km_since": 12000,
            "recommendation": "Просрочено на 2000 км"
        },
        ...
    ]
