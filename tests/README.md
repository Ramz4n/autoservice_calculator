# Автотесты

Тесты запускают настоящую программу (`AutoServiceApp`) на **тестовой** базе, заполняют формы и нажимают
кнопки как администратор, а результат проверяют запросами к базе и по тому, что показывают
«Отчёты», «Статистика», «Финансы».

## Запуск

```
python tests/run_all.py            # все тесты
python tests/run_all.py edit hint  # только тесты, в имени которых есть edit или hint
```

Коротко итог — в консоли, подробный лог — `tests/last_run.txt`. Код выхода 0 — всё прошло.
Полный прогон — несколько минут; на экране мелькает окно программы — это нормально.

## Безопасность

- Тесты **пишут в базу**, поэтому запускаются только если в `config/.env` есть `ALEXAN_TEST_DB=1`.
  Флаг стоит только на компьютере разработчика (`.env` не попадает ни в git, ни в релиз).
  **На базе клиента этот флаг не ставить.**
- Перед тестами — резервная копия в `Backup`.
- После тестов удаляется всё, что они создали (строки с id больше, чем были до запуска), должности
  и пароль для отчётов возвращаются как были. Это тоже проверяется («после уборки база как до тестов»).
- Наружу ничего не уходит: уведомления клиенту (Telegram, SMS) и обмен с сайтом в тестах подменены.
- Тестовые данные — на свои госномера и телефоны (`Т1xx`/`Т2xx`/`Т3xx`/`Т4xxТТ799`, `+79000000xxx`), имена «Тест …».
  Если такие уже есть в базе, набор не запускается.

## Файлы

| Файл | Что внутри |
|---|---|
| `harness.py` | Обвязка: запуск программы, автоответы на окна-вопросы, заполнение форм (`booking_form`, `works_form`, `warehouse_form`, `edit_form`), `check`, `expect_rejected`, уборка |
| `test_positive.py` | Позитивные проверки: сохраняется то, что нужно |
| `test_negative.py` | Негативные: неверный ввод → предупреждение и **ни одной** записи в базе (`expect_rejected`) |
| `test_effects.py` | Связи между разделами: действие доходит куда нужно (зарплата, доход, прибыль, «Статистика», «Финансы») и убирается при удалении |
| `test_pairwise.py` | Парные сочетания «Добавить работу» и «Записать клиента»: пары верных значений → всё сохранено и вопросы ровно где нужно; неверные значения на каждом пути → отказ |
| `pairwise.py` | Генератор парного набора (без внешних библиотек) и проверка, что покрыты все пары |
| `run_all.py` | Запуск наборов, фильтр по имени, итог |

## Методы: классы эквивалентности, границы, пары

**Классы эквивалентности.** Значения поля, с которыми программа поступает одинаково, — один класс; из класса
берём одного-двух представителей. Таблица ниже — какие классы есть у каждого поля и где они проверены
(П — `test_positive.py`, Н — `test_negative.py`, Пары — `test_pairwise.py`). Правила для чисел — одни на все
формы, в `input_rules.py`; для марки и модели — `car_catalog.py`.

| Поле | Верные классы | Неверные классы | Где |
|---|---|---|---|
| Цена работы / запчасти, сумма премии / выплаты / расхода | целое; дробное через `,` или `.`; с пробелами между разрядами (`1 500`); `12.`, `.5` | пусто; 0; минус; знак `+`; буквы; `nan`, `inf`, `1e5`; две запятые; меньше 0,005 (округляется до 0); больше 99 999 999,99 | П `test_input_rules_boundaries`, `test_boundaries_in_forms`; Н `test_works_rejects`, `test_payment_rejects`, `test_finance_rejects` |
| Цена на складе | как выше; пусто (цена пока неизвестна) | как выше, кроме пустой | П, Н `test_warehouse_rejects` |
| Количество на складе | пусто (= 1); целое 1…9999 | 0; минус; дробное; больше 9999; буквы | П, Н `test_warehouse_rejects` |
| Процент мастера | 0…100, дробный | меньше 0; больше 100; `nan`; буквы | П `test_input_rules_boundaries` |
| Пробег | пусто; цифры до 7 знаков; больше или равен прошлому; меньше прошлого и «Да» | буквы (убираются при вводе), с буквами, больше 7 цифр; меньше прошлого и «Нет» | П `test_work_mileage_*`, `test_boundaries_in_forms`; Н `test_works_rejects`; Пары |
| VIN | пусто; 17 символов; короче 17 и «Да»; другой, чем у машины, — «перезаписать?» («Записать клиента» — перезаписывается без вопроса: VIN машины уже подставлен в поле); 18-й символ обрезается | короче 17 и «Нет»; VIN другой машины (новой и найденной) | П `test_booking_vin`; Н `test_works_rejects`, `test_edit_rejects`, `test_booking_rejects`, `test_booking_vin_time_rejects`; Пары (обе формы) |
| Своё время записи | пусто (время кнопкой); `11:30`, `9.15`, `9 05`, `11-30`; `1130`, `930`, `9`, `11:` (= 11:00); 00:00…23:59; при вводе «:» сама, вторая не ставится, буквы убираются; сегодня — позже текущего | 24:00; минуты 60+; буквы; `1:5`, `11:3`; 5 цифр; с секундами; сегодня и уже прошло | П `test_booking_custom_time` (и сегодня через 2 минуты), `test_input_rules_boundaries`; Н `test_booking_rejects`, `test_booking_vin_time_rejects` (ровно «сейчас»); Пары |
| Телефон | 10 цифр после +7; пусто и «Да» (вопрос) | 1…9 цифр; пусто и «Нет» | П, Н `test_*_rejects`; Пары |
| Марка и модель | из справочника; другим регистром (записывается как в справочнике); у машины из базы — как записано, даже не из справочника | пусто; марка не из справочника; модель не этой марки | П `test_work_brand_from_catalog`, `test_edit_data`; Н `test_*_rejects`; Пары |
| Госномер | по образцу (латиница → кириллица) | пусто; без первой буквы, буква «Г», не по образцу — и «Нет»; чужой (у другой машины) | П, Н `test_*_rejects` |

**Граничные значения.** На каждой границе проверяем значение на ней и соседнее за ней:

| Граница | Проходит | Не проходит |
|---|---|---|
| Цена / сумма снизу | 0,01; 0,005 (→ 0,01) | 0; 0,004; 0,001 |
| Цена / сумма сверху | 99 999 999,99 | 100 000 000; 99 999 999,996 |
| Количество | 1; 9999 | 0; 10 000 |
| Процент | 0; 100 | −0,01; 100,01 |
| Пробег, длина | 7 цифр | 8 цифр (обрезается при вводе), 9 цифр (отказ) |
| Пробег меньше прошлого (прошлый 500 / 123) | 500 → 500; 500 → 501 | 123 → 122 (вопрос, «Нет» — не сохранено) |
| VIN | 17 символов — без вопроса | 16 — вопрос; 18-й символ — обрезается |
| Телефон | 10 цифр | 9 цифр |
| Своё время записи, часы и минуты | 00:00; 23:59 | 24:00; 11:60 |
| Своё время записи сегодня | через 2 минуты | ровно текущая минута; 00:00 |

**Парное тестирование** — `test_pairwise.py`. Факторы «Добавить работу»: машина (новая / из базы),
запись (нет / есть), телефон (вписан / стёрт), пробег (пусто / больше / меньше прошлого), VIN (пусто / 17 / 16),
марка (как в справочнике / маленькими буквами). Все сочетания — 144 (с ограничением «запись только у машины
из базы»), парный набор — около 16 строк: каждая пара значений любых двух факторов встречается хотя бы раз
(это проверяет сам тест). Для каждой строки известно, что должно получиться: наряд с этим пробегом, VIN у машины,
марка «Kia Rio», привязка к записи, и какие вопросы должны быть (пробег меньше, VIN не полностью, перезаписать
VIN, без телефона, телефон стёрли), а каких — нет.
Неверные значения (нет мастера, 9 цифр телефона, марка не из справочника) в пары **не** смешиваются — форма
отклонила бы строку целиком, и остальные пары не проверились бы; они проверяются отдельно на каждом пути
(новая машина / из базы / по записи).
Новый фактор или значение — дописать в `FACTORS` и в ожидания (`expected_asked`, проверки базы) в
`test_pairwise_work_saved`.

Факторы «Записать клиента» (`BOOKING_FACTORS`): машина (новая / из базы со своим VIN), VIN (оставить, как
подставился / 17 / 16 / стёрли — у новой машины стирать нечего), время (кнопкой / своё), мастер (любой /
конкретный). Все сочетания — 28, парный набор — 8 строк. У каждой строки свой день (чужие записи не занимают
мест). Неверные значения (VIN другой машины, своё время 25:00) — отдельно на новой машине и машине из базы.

## Как добавить проверку

1. Позитивная — функция `test_…(h)` в `test_positive.py`, в конце добавить её в `TESTS`.
   Заполнить форму через `h.*_form(...)`, проверить базу через `h.q(...)` и `h.check(...)`.
2. Негативная — в `test_negative.py`: `h.expect_rejected("что проверяем", действие, "часть текста предупреждения")`.
   Если программа задаёт вопрос «Да/Нет» — `answers=[False]` (ответить «Нет»).
3. Связи между разделами — в `test_effects.py`: снять «до» (`h.report()`, `h.stats()`), сделать действие,
   проверить **изменение** («доход +2000»), потом отменить действие (удалить) и проверить, что всё как было.
   Помощники: `h.report()`, `h.stats()`, `h.give_bonus()`, `h.complete_booking()`, `h.delete_booking()`,
   `h.delete_expense_in_finances()`, `h.finance_entry()`, `h.finance_rows()`, «Другой период» — `h.passwords` (ответы окну пароля), `h.set_period()`, `h.period_locked_ui()`, вопрос «новый владелец?» — `h.owner_question(True)` (по умолчанию в тестах он считается неожиданным окном), склад — `h.warehouse_part()`, `h.warehouse_set_status()`,
   `h.works_add_from_warehouse()`, `h.works_remove_part()`.
4. Новые госномера / телефоны — в `PLATES` / `PHONES` набора (проверяются на занятость перед запуском).
   Новое поле ввода — его классы и границы дописать в таблицы «Методы» выше и проверить на границе и за ней.
5. Обновить таблицу «Что покрыто» выше.
